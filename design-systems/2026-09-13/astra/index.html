Design system / 0.2.0 / Beta

Astra design system

Origin: the Codex round of 2026-09-13, which Jack refers to as Astra · Source folder local-only/codex-design-2026-09-13/outputs/redesign/ · Produced by Codex (model version not recorded in the round's output) · Rebuilt to SPEC.md on 2026-09-13

Astra is the design system for www.jackzhaojin.com. Serif display type on a sans body, one violet accent, lavender tint panels, a deep plum panel for featured content, numbered mono kickers and question-shaped section headings. Light and dark are two token sets on one system, light by default. Every component is documented here with live stories in both themes.

What are the principles?

  1. Content is in the HTML. JavaScript switches theme, opens the mobile nav, filters and sorts. It never supplies or hides content.
  2. Headings ask, body copy answers. Serif H2s are phrased as the question a reader or an answer engine would ask. The paragraph under them answers in plain words.
  3. One accent. Violet marks links, kickers and the flagship topic. Everything else is plum ink on lavender tints.
  4. Facts in tables, steps in lists. People and parsers read the same structure. No styled div grids for data.
  5. Two palettes, one system. Every component is checked in light and dark, and every text pair meets WCAG AA in both.

Quick start

Three stylesheets in this order, the shared theme script deferred, and data-theme-default="light" on the root element. The pre-paint snippet in the Theming section goes in the head before the stylesheets.

<html lang="en" data-theme-default="light">
...
<link rel="stylesheet" href="tokens.css">
<link rel="stylesheet" href="base.css">
<link rel="stylesheet" href="components.css">
<script src="../shared/theme.js" defer></script>

Files: tokens.css, tokens.json, base.css, components.css, scripts.js (blog filters only), templates/, and README.md for agents and people who read text.

Buttons use sm, tables and panels use md, cards use lg, chips use pill. The vendor round's 8 / 6 / 5 px values are kept.

Shadows

--shadow-1
--shadow-2

Cards rest on shadow-1 and lift to shadow-2 on hover. Panels, tables and chips have no shadow. Dark shadows are black at higher opacity so they still read against plum.

08 / Foundations

How does light, dark and system work?

Light is the default. A three-state control persists the choice under the localStorage key jj-theme with values light, dark or system. The pre-paint snippet in the head reads the key before any stylesheet loads and sets data-theme on the root element, or removes it for System so the media query decides. The shared shared/theme.js syncs aria-pressed, sets data-theme-effective, follows OS changes while in System and toggles the mobile nav. It is not forked.

Live control (the same one as in the header)

Pre-paint snippet

<script>
(function(){var d=document.documentElement;d.classList.add('js');try{var s=localStorage.getItem('jj-theme');var def=d.getAttribute('data-theme-default')||'light';var c=(s==='light'||s==='dark'||s==='system')?s:def;if(c==='system'){d.removeAttribute('data-theme');}else{d.setAttribute('data-theme',c);}d.setAttribute('data-theme-choice',c);}catch(e){}})();
</script>

Selector structure in tokens.css

:root, [data-theme="light"] { color-scheme: light; /* light semantic tokens */ }
[data-theme="dark"] { color-scheme: dark; /* dark semantic tokens */ }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]):not([data-theme="dark"]) { color-scheme: dark; /* dark semantic tokens, duplicated */ }
}

Because [data-theme="dark"] matches any element, a frame can be forced to one theme. Every dark story on this page is a <div class="story" data-theme="dark"> inside a light page.

Rules

  • data-theme-default="light" on every page in this round. system is reserved for the portfolio later.
  • Never read the theme in CSS from anything but the tokens. Components do not know which theme is active.
  • The wordmark contains the text "Jack Jin" only. No glyph, half circle or theme symbol.

Do / Don't

Do
Keep the band outside the container; keep its content inside. Match a topic wash to the section's topic.
Don't
Don't put two alternate bands together, nest bands, or use more than one inverse band per template.

Accessibility

  • Use a real section heading and aria-labelledby. Story headings use paragraphs to preserve the documentation outline.
  • Wash and dots are decorative CSS layers, ignore pointer events and never change text color. Information must remain in HTML.
  • Keep normal text at 4.5:1 on the combined wash; keep controls and focus visible. Milestone numerals use solid text so a year remains readable.
  • The two inverse previews above are separate component examples, not a page composition. Templates allow one inverse band at most.

10 / Patterns

How is a page put together?

Page anatomy

  1. Skip link, site header.
  2. Breadcrumb (every page except home), directly above the H1.
  3. Page head: kicker, H1, byline with published and updated dates, summary of 40 to 60 words.
  4. Facts table right under the summary on post and project pages.
  5. Body: H2 sub-questions, ol for steps, table for comparisons, embed with a plain link, chapters, transcript.
  6. FAQ, related items, author box, then the footer.

Section rhythm

  • Home: page head plain; topics tint with the AEM + AI accent; latest posts alt; featured project tint with the page accent and dots; credentials plain, opened by the labeled divider; talks tint with the Working with AI accent; CTA inverse. The contained Anima Mesh panel stays plum.
  • Post: breadcrumb, page head, facts, embed, chapters, body, transcript and FAQ in one plain band; related items, Discuss on LinkedIn and author box in one alt band.
  • Blog: breadcrumb and page head plain; featured intro and counts tint with the page accent; filters and all 39 cards plain; FAQ alt.

This follows section 9 without rebalancing. Bands alone fill the viewport between header and footer; containers center their content. Each band has a top hairline and fluid padding. Adjacent bands need visibly different grounds in both themes; two alt bands never touch. Topic tints follow the topic; otherwise use the page accent. Washes never change text colors. Use at most one inverse band per template. Milestones are optional short breaks with top and bottom hairlines; none is added to these templates because no content calls for one.

Heading rules

  • One H1. H2 for sections, H3 for items inside them, never skipping a level.
  • Section H2s are phrased as questions a reader would ask, and the first paragraph answers them.
  • Titles and H1s spell out Adobe Experience Manager (AEM), Edge Delivery Services (EDS) and DA.live.

Content in HTML

Every list, table and transcript ships in the initial HTML. JavaScript may switch theme, open the nav, filter and sort. It never fetches, supplies or hides content by default, and there are no opacity-zero reveal patterns.

Images and alt text

  • Alt text is one sentence naming what a diagram shows and the entities in it.
  • Decorative images get alt=""; decorative SVG gets aria-hidden="true".
  • No fact lives only inside an image. This round ships no card art at all.

Theme default

data-theme-default="light" on every page. The value system is reserved for the portfolio page later.
