Design system / round 2026-09-13 / kimi-k3

kimi-k3 design system

Version 0.1.0 · Status draft candidate · 2026-09-13 · Origin: the Kimi K3 round

Developer editorial: Inter for everything you read, IBM Plex Mono for everything you look up. Near-black on off-white with one electric blue, square corners, one pixel rules, "//" section labels and bracketed chips. Light by default, dark as a second token set, content always in the HTML.

Identity

The round read like an engineer's ledger: ink on paper, hairline rules, mono metadata, one accent. This system keeps that. One sans family (Inter) carries display, headings and body; one mono family (IBM Plex Mono) carries labels, chips, bylines, tables and code. Mono is the voice of facts, sans is the voice of prose. The accent is a single electric blue in light and a lavender in dark. Corners are square, borders are one pixel, there are no shadows. The identity marks are the accent "//" before every kicker, bracketed mono chips, an accent highlight behind one key phrase, and the wordmark's blinking underscore cursor. What was dropped from the round: em dashes as a device, the deferred theme script, the opacity-zero reveal, the invented content and the three-plus-one hub grid.

Principles

  1. Content is in the HTML. Scripts switch theme, open the nav, filter and sort. They never supply, fetch or hide content.
  2. Ink on paper, one accent. Color says one thing: this is a link, a label or a topic.
  3. Mono is the voice of facts. Anything that is data (dates, counts, labels, tables) is set in IBM Plex Mono.
  4. Hairlines, square corners, no shadows. Structure comes from rules and alignment.
  5. Facts over adjectives. Every number comes from data; unknowns stay bracketed.

Wide screens

At 1920 and 2560 the container stays at 1216px and centers; the margins grow equally on both sides. Section rules span the container, not the viewport, so the page reads as a centered column. Nothing sits flush left. Fluid type stops growing at 1200px (the clamp maximums), so headings do not balloon on large monitors.

Shape and elevation

Square. --radius-sm 0 on cards, tables, buttons and chips. --radius-md and --radius-lg 2px on inline code and marks. --radius-pill is 2px because the system has no pills; chips are bracketed mono text instead. Every border is --border-width 1px. --shadow-1 is none; --shadow-2 is a one pixel hairline offset reserved for the sticky header.

Theming

Light and dark are two token sets on one system; light is the default. A three-state control persists the choice under the localStorage key jj-theme with the values light, dark and system. The pre-paint snippet in the head reads the key before any stylesheet loads and sets data-theme on the root element, so there is no flash. shared/theme.js (deferred, never forked) wires the buttons, keeps aria-pressed in sync, sets data-theme-effective and follows OS changes while in System.

Live control

Pre-paint snippet

<script>
(function(){var d=document.documentElement;d.classList.add('js');try{var s=localStorage.getItem('jj-theme');var def=d.getAttribute('data-theme-default')||'light';var c=(s==='light'||s==='dark'||s==='system')?s:def;if(c==='system'){d.removeAttribute('data-theme');}else{d.setAttribute('data-theme',c);}d.setAttribute('data-theme-choice',c);}catch(e){}})();
</script>

Selector structure

:root, [data-theme="light"] { color-scheme: light; /* light semantic tokens */ }
[data-theme="dark"] { color-scheme: dark; /* dark semantic tokens */ }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]):not([data-theme="dark"]) { color-scheme: dark; /* dark semantic tokens, duplicated */ }
}

Because the dark set is bound to [data-theme="dark"] on any element, a nested frame can be forced to one theme. Every dark story on this page is a div.story[data-theme="dark"] inside a light page. Components read color tokens at the use site, never through a component token defined on the root, so the nested frame re-themes everything inside it.

One subsection per component. Each follows the Storybook docs pattern: status, when to use it, anatomy, one live story per variant and state, at least one dark story, the canonical markup, do and don't, accessibility notes and the tokens it consumes. Do and don't

Do

  • Use real links; the nav carries the most weight for search.
  • Mark the current section with aria-current="page".
  • Keep the wordmark text only.

Don't

  • Do not put an icon, image or glyph inside the wordmark.
  • Do not hide the nav without JavaScript.
  • Do not add a fourth theme state.

Accessibility

  • Menu button exposes state through aria-expanded; the nav is labeled Primary.
  • The wordmark cursor blink stops under prefers-reduced-motion.
  • Nav text uses text-muted, 10.41:1 light and 12.71:1 dark.

Card stable

A bordered block with a mono meta row, a title link, an excerpt and a footer. Three kinds: post, hub (numbered) and project (period, facts line, repo link). The title is the link; the card is not, though a CSS pseudo element extends the hit area over the card. Inside .grid--rules the cards share hairlines.

  • article.card plus .card--post, .card--hub or .card--project
  • p.card__meta (chips and a time)
  • h3.card__title with the link
  • p.card__excerpt
  • p.card__footer (topic chip or counts)
  • hub only: p.card__number; project only: p.card__period, p.card__facts, a.card__link

Tokens used

currentColor only; no color tokens of its own

Patterns

Page anatomy

  1. Breadcrumb, directly above the H1, on every page except home.
  2. Kicker and H1. The H1 is the page's subject, not a slogan. Titles say Adobe Experience Manager (AEM), Edge Delivery Services (EDS) and DA.live in full.
  3. Byline with author link, published and updated dates, read or watch time and the media type.
  4. Summary: the 40 to 60 word answer block, first, with nothing between it and the H1.
  5. Facts table.
  6. Body in a .prose column: H2s phrased as the questions people ask, steps in ol, comparisons in table.table.
  7. FAQ, related links, author box.

Heading rules

One H1. Then H2 and H3 in order; never skip a level. Cards use h3 under a section h2. Footer columns use h2. Component subsections on this page use h3 with h4 parts.

Content in HTML

Every slot ships in the initial HTML. Tabs, accordions and carousels only when the content stays in the DOM (details, or hidden toggled by JavaScript) and the default view shows the summary, the facts table and the first section. No opacity-zero reveal patterns.

Images and alt text

Alt text is one sentence naming what a diagram shows and the entities in it. Decorative images get alt="". Decorative SVG gets aria-hidden="true". No fact lives only inside an image. This round uses no raster images; the monogram avatar stands in for the headshot.

Theme default

Every page in this round sets data-theme-default="light". The value system is reserved for the portfolio page later. Never hard code data-theme in the HTML; the pre-paint snippet sets it.

Voice

An engineer's plain voice. No slogans, no hype, no filler adjectives. Link labels name the destination. Numbers come from data or stay bracketed. No em dashes or other unicode dashes anywhere; use a slash, a comma or a new sentence.

Why each slot exists, for humans, search and AI answer engines: seo-page-blueprint.md.

Templates

  • Home: H1 and positioning, summary, four hub cards, latest three posts, featured project with facts, credentials strip, six talks, CTA band.
  • Post, video state: the Adobe Stardust post with byline, facts, embed placeholder, chapters, question-shaped H2s, comparison table, transcript, FAQ, related, author box.
  • Blog: all 39 posts newest first, counts by facet, filter bar with query string state, FAQ. No pagination under 48 items.

Hub links point to blog.html?topic=<slug> because hub pages are not built in this round.
